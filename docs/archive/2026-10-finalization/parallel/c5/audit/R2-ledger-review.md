## 3. RESEARCH rows — recommendation

### M-071 — i18n (kept as RESEARCH)

Recommendation: **adopt the plan in R2-i18n-theme.md A.5–A.9, but start with two phases that need no approval and change no visible text**, and sequence it behind the S3 text work.

1. **Order matters.** S3's glossary and terminology fixes (M-060 … M-063) change thousands of strings. Extracting 4,300 strings into a catalogue **before** that means translating inconsistent text. So: S3 normalises first; the catalogue then takes the normalised text.
2. **Phase 0 (C5-only, ≈1 day, no UI change):** `@xweb/i18n` gets a provider with only `vi`, locale-aware `fmtDate/ago/num/usd/tok` that output exactly what they print today, `<html lang>` from the locale, delete the two private `fmtDate` copies (`drawers.tsx:15`, `ReleaseModal.tsx:18`). Add the **ratchet**: re-use `scripts/r2-i18n-count.mjs` as a unit test with a recorded per-file baseline; a file's count may not grow. Baseline is regenerated once after S3's text pass.
3. **Phase 1 (C5-only, no UI change):** move the ~970 strings that already sit in pure modules (label maps, validators, `explainError`, `STATE_TEXT`, role/portal maps) into `locales/vi.ts`; this also removes the four role tables (M-062) and the second portal-name table.
4. **Gate before phase 2:** a product decision that a second locale is wanted (C0 / product). Without it, stop after phase 1: the catalogue still pays for itself (one place for terminology, a test that every enum has a label — M-061).
5. **Phase 2 (pilot, needs the decision):** shell + auth pages (~300 strings) in `en`, cookie + `Accept-Language` through the existing `proxy.ts` (`x-locale`), pseudo-locale in the harness; no path prefix. Phase 3 is opportunistic per touched screen.
6. **Dependencies:** a message-format library needs `package.json` (C0); locale/time-zone preference needs C1 (HF-C1-06); site language needs C2 (HF-C2-05). None of them blocks phases 0–1.
7. **Not recommended:** a codemod over all strings; a `/{locale}/` path prefix (collides with `PORTAL_PREFIX`, `portalOfPath`, `safeNext`, `basePath`, OIDC and activation URLs).

Acceptance numbers: phase 0 — `vi` output byte-identical on the existing unit tests; phase 1 — strings in non-TSX modules ≈970 → <100, role tables 4 → 1; ratchet green.
