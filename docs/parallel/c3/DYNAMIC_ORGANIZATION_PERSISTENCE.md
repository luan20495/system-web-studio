## 2. Schema (6 tables, additive, V20 `departments` untouched) - `dynamic-organization-V32.pending.sql`

| Table | Notes |
|---|---|
| `organization_unit_types` | `id`, `tenant_id`, `code` (unique per tenant, case-insensitive), `name`, `icon`, `rules JSONB` (`OrgUnitTypeRules` document, applied by C1), `active`, `version` (starts 0), timestamps. |
| `organization_units` | adjacency list: `type_id`, `parent_id` (NULL = root), `code` VARCHAR(60) upper-case, `name`, `sort_order`, `metadata JSONB`, `active`, `deleted_at`, `version`. CHECKs: not self-parent, code form, `deleted_at IS NULL OR NOT active` (no contradictory row), metadata is an object. |
| `employee_organization_units` | membership: `id`, `user_id`, `organization_unit_id`, `relation_type` (`^[A-Z][A-Z0-9_]{0,31}$`, business vocabulary only), `is_primary`, `active` (ending = `active FALSE`, row stays), `version`. `UNIQUE (id, tenant_id, user_id)` is the target of the position FK. |
| `positions`, `grades` | independent taxonomies; `description` nullable; `grades."rank"` nullable, not unique; no grade on a position (it belongs to the employee position). |
| `employee_positions` | `employee_organization_unit_id` (membership), `position_id`, `grade_id` NULL, `is_primary`, `active`, `version`; the unit is derived by a join, never copied. |

**Tenant isolation (database):** every table `tenant_id NOT NULL REFERENCES tenants`; `UNIQUE (id, tenant_id)` + composite FKs `(x_id, tenant_id)` for unit -> parent / type, membership -> unit, employee position -> position / grade; membership -> `tenant_members(tenant_id, user_id)` (the canonical employee; it is also why a member with memberships cannot be deleted); employee position -> membership `(id, tenant_id, user_id)` (a position can only be held in a membership of THE SAME employee, which also pins the unit to the tenant). `parent_id` NULL is a root (MATCH SIMPLE). All `ON DELETE RESTRICT`: nothing cascades.

**Indexes (each with the query it serves):**
| Index | Serves |
|---|---|
| `organization_units_sibling_code_unique (tenant_id, parent_id, code) NULLS NOT DISTINCT WHERE deleted_at IS NULL` | sibling-scoped code (roots included), archive frees the code, restore / move / rename collision |
| `organization_units_children_idx (tenant_id, parent_id, sort_order, name, id)` | children in display order, roots, `activeChildCount`, every recursive step, parent-FK check |
| `organization_units_type_idx (tenant_id, type_id)` | type-FK check, units of a type |
| `organization_unit_types_code_unique`, `positions_code_unique`, `grades_code_unique` `(tenant_id, lower(code))` | case-insensitive per-tenant code, also when disabled |
| `employee_organization_units_active_unique (tenant_id, user_id, organization_unit_id) WHERE active` | one ACTIVE membership per (employee, unit) |
| `employee_organization_units_one_primary_idx (tenant_id, user_id) WHERE is_primary` | at most one active primary membership per employee |
| `employee_organization_units_unit_idx (tenant_id, organization_unit_id, user_id) WHERE active` | `activeCountByUnit`, counts, directory unit filter |
| `employee_organization_units_user_idx (tenant_id, user_id)` | membership lookup of a page |
| `employee_positions_active_unique (employee_organization_unit_id, position_id) WHERE active` | one active assignment per membership + position (also the active-positions count of a membership) |
| `employee_positions_one_primary_idx (tenant_id, user_id) WHERE is_primary` | one primary position per employee |
| `employee_positions_user_idx`, `_position_idx`, `_grade_idx` (partial `WHERE active`) | page enrichment, directory position / grade filters |
Not created (measured / argued): `(tenant_id, active)` on units (no query filters on it alone), a name / code search index (the directory search is a bounded scan: ~14 ms EXPLAIN at 12k users), `pg_trgm` (never enabled by any migration; prototype evidence in `PROTOTYPE_BENCHMARK.md` on branch `agent/c3-org-v32-proposal`).

## 3. Repositories (`com.systemwebstudio.data.org`, main code) - implement the C1 seams EXACTLY

`PostgresOrganizationUnitTypeRepository`, `PostgresOrganizationUnitRepository`, `PostgresEmployeeDirectoryRepository`, `PostgresEmployeeOrganizationMembershipRepository`, `PostgresPositionRepository`, `PostgresGradeRepository`, `PostgresEmployeePositionRepository`, `PostgresTenantStructuralLock`; plain `JdbcTemplate`, one ambient transaction (`PROPAGATION_REQUIRED`: never REQUIRES_NEW, never a second connection).
- **Versioned writes:** one `UPDATE ... WHERE tenant_id AND id AND version = ?` (`RETURNING` on units), `null` when stale or missing.
- **Typed refusals:** `DuplicateOrganizationKey(code | membership | assignment | primary)` mapped from the constraint name, `OrganizationUnitInUse`, `MembershipHasPositions`, `ReferencedRowInactive("unit" | "membership")`, `OrganizationCycle`; anything else is rethrown.
- **Race safety without a tenant-wide lock:** a child insert / move destination / membership insert / restore takes `FOR SHARE` on the unit row and refuses an archived one; archive takes `FOR UPDATE` on the unit and then counts ACTIVE children and memberships; ending a membership takes `FOR UPDATE` on it and counts active positions; `setPrimary` locks the employee's active rows in id order and the partial unique index is the backstop. Proved by `OrgRaceTests` (never a contradictory state in 140 racing rounds).
- **`move`:** takes the tenant advisory lock itself too (re-entrant: C1's service already holds it), re-checks the cycle in the store, refuses a sibling code clash and an inactive destination, CAS on the version, descendants are not rewritten.
- **maxDepth (CF-4 residual race):** re-checked inside `insert` and `setActive(true)` under the parent row lock (409 `ORG_TYPE_RULE_VIOLATION` reason `MAX_DEPTH`, the same refusal as C1's service). A concurrent move of an ANCESTOR can still slip through in a rare race; documented limit of the contract.
- **Bounded waits:** one `SET LOCAL lock_timeout` per transaction (default 5 s, `app.organization.lock-timeout-ms`); a writer that cannot get a row / structural lock in time fails with **`503 ORG_STRUCTURE_BUSY` + `Retry-After: 1`** (SQLSTATE 55P03 only). **This code is NOT in the C1 contract: C1 must acknowledge it** (otherwise it is an unmapped 503).
- **Directory:** `tenant_members JOIN users`, page first (filter + stable sort + LIMIT / OFFSET on the members only; unit / position / grade filters are `EXISTS`, so a multi-membership person is one row); C1 enriches the <= 100 ids with `listForUsers` (one query per kind). Sort `lower(coalesce(display_name, username))` or `lower(username)`, ties by user id. Bounded offset: page * size > 10,000 answers an empty page with the true total (**C1 does not bound the offset today**: it should answer 400).
- **Extra reads (not in the C1 seams):** `listRoots`, `listChildren`, `ancestors`, `descendants` / `fullTree` (bounded, depth-first, depth, no employee data) and `PostgresOrganizationCounts` (`directMemberCount`, `subtreeEmployeeCount` = `COUNT(DISTINCT user_id)`, per tree level or whole tree). The frozen C0 EMPLOYEE_COUNT needs both counters; C1's seam only has `activeCountByUnit` (memberships). **C1 should consume `PostgresOrganizationCounts`** (C5 shows `employeeCount`).

C0 / C7 targets (children p95 < 200, search page p95 < 300) are met with a wide margin. Concurrency (pool 10 = the production default, 100 simultaneous threads): 100 mixed ops over 10 tenants 174 ops/s (p95 511 ms); 100 structural moves in one hot tenant 165 ops/s (p95 590 ms); lock_timeout 20 ms: 14 clean `LOCK_TIMEOUT`, 0 deadlocks; 50 A<->B pairs: 50 OK + 50 CYCLE; graph acyclic in all 11 tenants. ## 8. Findings / decisions for C0 and C1
1. **Tenant hard delete is restricted by design** (`ON DELETE RESTRICT`): a tenant with organization rows cannot be `DELETE`d (C1's own test cleanup had to remove them first, see `OrganizationOnPostgresApiTests`). Tenant lifecycle is `status`; C0 / C1 should say so before any tenant-purge job.
2. `ORG_STRUCTURE_BUSY` (503, retryable) is new: acknowledge or rename. 3. The directory offset bound (<= 10,000) belongs in C1's validation (400). 4. `subtreeEmployeeCount` / `directMemberCount` are available but not consumed. 5. Types / positions / grades have no archive, so no `deleted_at` on them (only if C1 adds archive to the API). 6. Memberships and employee positions end by `active = false` (the link-row convention): a membership row is never reused, a new one is inserted. 7. The kit pins versions starting at 0.
