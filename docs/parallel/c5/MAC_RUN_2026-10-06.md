## 3. Rebuild and run (exact commands)

```
cd <C5 checkout> && npm ci
docs/parallel/c5/e2e-stack.sh up                 # worktree + env + containers + backend + render worker + Studio; ≈ 2 min cold, 30 s warm
docs/parallel/c5/e2e-stack.sh status
docs/parallel/c5/e2e-stack.sh e2e                # the whole suite; or:  e2e E2E-01,E2E-02
E2E_SHUFFLE_SEED=11 docs/parallel/c5/e2e-stack.sh e2e         # shuffled order (stability)
docs/parallel/c5/e2e-stack.sh e2e E2E-04,E2E-05           # permission contract (PERMISSION_CONTRACT.md)
docs/parallel/c5/e2e-stack.sh down --infra --worktree          # cleanup (the state dir stays; delete it by hand)
node scripts/e2e-stability-summary.mjs .run/e2e-real           # per-flow table over every report found
```

The script's sub-commands (`prepare`, `infra-up`, `backend-up`, `backend-launch`, `backend-down`, `backend-restart`, `backend-pause`, `backend-resume`, `render-up`, `studio-up`) are also the hooks the suite uses (`E2E_RESTART_BACKEND_CMD`, `E2E_STOP/START_BACKEND_CMD`, `E2E_PAUSE/RESUME_BACKEND_CMD`). It was tested on 2026-10-07 on a second instance (`E2E_STACK_NAME=c5e2e-t`, ports 48080/45432/46379/49000/45672/48088/48095, Studio 3013): cold worktree to green in 29 s on a warm Gradle cache, then the whole suite.

### What the script does, for anyone who wants to do it by hand

- **Containers** (prefix `$E2E_STACK_NAME`, default `c5e2e`; never the `hbl-*`, `hblpub-*`, `factory-*`, `chatwoot-*` ones): `<name>-pg` postgres:17.6, `-redis` redis:8.2.1-alpine, `-minio` bitnamilegacy/minio:2025.7.23-debian-12-r5 (bucket `studio-assets`), `-rabbit` rabbitmq:4-management-alpine, `-sites` nginxinc/nginx-unprivileged:1.29-alpine with `infra/sites-gateway/default.conf.template` and `API_UPSTREAM=host.docker.internal:<api port>`.
- **Env vars (names only; values random, kept in `stack.env`)**: `DATABASE_URL/USER/PASSWORD`, `REDIS_HOST/PORT`, `MINIO_ENDPOINT/ROOT_USER/ROOT_PASSWORD`, `RABBITMQ_HOST/PORT/USER/PASSWORD`, `LOCAL_ADMIN_PASSWORD` (14+ chars; seeds the system admin `local.admin`, profile `local`), `SECRETS_MASTER_KEY` (base64, 32 bytes; without it a credential write is 500 `SECRETS_UNAVAILABLE`), `COOKIE_SECURE=false`, `SPRING_PROFILES_ACTIVE=local`, `SERVER_PORT`, `CORS_ALLOWED_ORIGINS` / `WEB_ORIGIN_STUDIO` (the Studio origin exactly), `MAX_PROJECTS_PER_WORKSPACE=100000`, `DATA_PLATFORM_ENABLED=true`, `WORKFLOW_ENABLED=true`, `DEPLOY_PROVIDER=static`, `SITES_ORIGIN`, `STUDIO_ORIGIN`, `RENDER_URL`, `RENDER_PORT`, `RENDER_TOKEN`, `JAVA_HOME`.
- **Backend start**: `cd <worktree>/backend && ./gradlew bootRun --console=plain -Dorg.gradle.jvmargs=-Xmx3g -Pkotlin.daemon.jvmargs=-Xmx3g` with the env above; ready when `GET /actuator/health/liveness` is `UP` (≈ 25 s after compile). Flyway applies V1–V29.
- **Render worker**: `npx tsc -p workers/render/tsconfig.json`, then `RENDER_PORT=<p> RENDER_TOKEN=<t> node workers/render/dist/workers/render/server.js`; `GET /health` → `ok`.
- **Studio (frontend)**: `API_PROXY_TARGET=http://127.0.0.1:<api port> NEXT_DIST_DIR=.next-check-<name> npm run build:studio`, then `cd apps/studio && NEXT_DIST_DIR=… npx next start -H 127.0.0.1 -p <studio port>`. **The proxy target is baked in at build time**; setting it only on `next start` has no effect (every `/api` call is 500 `ECONNREFUSED :8080`). `NEXT_DIST_DIR` keeps this build apart from the normal `.next`, so a gate build does not break the running Studio.
- **E2E command**: `E2E_STUDIO_URL=http://127.0.0.1:<studio> E2E_ADMIN_USER=local.admin E2E_ADMIN_PASSWORD=<LOCAL_ADMIN_PASSWORD> E2E_CHROME=<chrome> E2E_DURABLE_RUN_STORES=1 E2E_RESTART_BACKEND_CMD=… npm run test:e2e:real` (variables: `docs/C5_REAL_BACKEND_E2E_RUNBOOK.md` §3.3).

`E2E_STACK_NAME` (c5e2e) · `E2E_STACK_DIR` (`~/.xweb-e2e-stack/<name>`) · `E2E_REPO` (the C5 checkout; default: where the script lives) · `E2E_BACKEND_REPO` · `E2E_BASE_REF` (`integration/v2`) · `E2E_MERGE_REFS` (empty; before `3333aa7` use `"wire/v29-run-persistence agent/c3-data-prod"`) · `E2E_API_PORT`, `E2E_PG_PORT`, `E2E_REDIS_PORT`, `E2E_MINIO_PORT`, `E2E_RABBIT_PORT`, `E2E_SITES_PORT`, `E2E_RENDER_PORT`, `E2E_STUDIO_PORT` · `E2E_JAVA_HOME` · `E2E_CHROME` · `E2E_OUT_DIR` (reports; default `<repo>/.run/e2e-real`). A merge conflict stops the script: nothing is resolved for you.

## 5. Evidence format (one reporter, no second framework)

Every run writes `report-*.json` and `evidence-*.txt` (`tests/e2e-real/lib/report.mjs`). Per flow: `FLOW, RESULT, START, END, FRONTEND_HEAD, BACKEND_HEAD, BACKEND_URL, PROJECT, WORKSPACE, HTTP EVIDENCE, UI ASSERTION, PERSISTENCE ASSERTION, RESTART/RECOVERY, BLOCKER, OWNER`. `E2E_BACKEND_URL` / `E2E_BACKEND_HEAD` (set by the script) fill the backend lines. A check's kind is inferred from its name (`kindOf`) unless a flow passes one.
