## The Studio admission rule as implemented
| Level | Rule | Code |
|---|---|---|
| Portal (`studio.build`) | `APP_VIEW` in some `workspaces[].permissions` OR in some `projectScopes[].permissions`; each scope judged alone; absent `projectScopes` / `permissions` = older backend, cannot say no | `capabilitiesOf` |
| ONE project (before any of it renders) | `APP_VIEW` in the project's workspace row, OR in the `projectScopes[]` row with the SAME `projectId` AND `workspaceId`; plus the project payload's own resolved list holds `APP_VIEW`. Malformed rows are ignored (fail closed when the field is present); absent field = cannot say no | `canAdmitProject` (`canonical.ts`) used by `ProjectWorkspace` (which also covers `CodeWorkspace`) |
| Never | role label; `APP_PUBLISH` / `APP_EDIT` / `APP_USE` / `APP_SHARE` / `TENANT_*` standing in for `APP_VIEW`; a scope merged into the workspace / global set; A admitting B | tests below |
