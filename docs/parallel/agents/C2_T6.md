## 2. Current architecture (đã đối chiếu code thật)
- **Modular Monolith** Kotlin 2.2 / Spring Boot 4.1 / JDK 21 / Jackson 3 (`tools.jackson`), package gốc `com.systemwebstudio` ở `backend/src/main/kotlin/...`. **Không phải microservices** — không được đề xuất/chuyển sang microservices.
- Backend khoảng 105 file Kotlin, ~20 module: `access admin ai asset audit code common component identity integration maintenance member project prompt publish runtime schema settings template version`.
- **Frontend Next.js ở ROOT repo** (không có thư mục `frontend/`): `app/ features/{admin,auth,studio} components/ lib/ e2e/`.
- PostgreSQL + Flyway (hiện tới **V25**), Redis (session), MinIO, RabbitMQ.
- Ngoài JVM có các plane riêng: render worker, build runner, Forgejo, nginx/site gateway, generated app containers.
- Hiện **chưa có**: multi-tenant thật (không có bảng `tenants`/`tenant_id`), Tenant Admin, group/department permission thật, ABAC, RLS, App Model hợp nhất, metadata DataSource/Query/ViewModel/Mapping/Transform, Schema Discovery, metadata Event/Action/Workflow. Đơn vị tổ chức thực tế là **Workspace**; Super Admin = `users.system_admin`; Tenant Admin gần nhất = `WORKSPACE_ADMIN`; quyền = workspace role + project role (`PermissionMatrix`); Department chỉ để báo cáo.
- `projects` chứa hai kiểu app: **PAGE_SCHEMA** (metadata JSON; AI sinh typed operations → `SchemaPatchEngine` → `PageSchemaValidator` → version bất biến; AI không sinh code tùy ý) và **STATIC_APP** (source trong Git/Forgejo, build sandbox, container có DB riêng). V2 **không** rewrite; V2 mở rộng PAGE_SCHEMA thành App Definition V2 theo hướng backward compatible.

Luồng dữ liệu chuẩn (đích): `UI → App Definition/ViewModel → Query|Action → Auth → Permission → Data Gateway → Connector → DB/REST/External → Mapping/Transform → UI`.
Luồng AI chuẩn: `Prompt → Structured Operation → App Definition → Validator → Version`. **AI không có model dữ liệu riêng.**

1. Đọc kỹ code thật: `schema/SchemaOperation.kt` (data class không có trường mang code; `OperationTypes`: `ADD_SECTION REMOVE_SECTION MOVE_SECTION UPDATE_SECTION UPDATE_PROP ADD_ITEM REMOVE_ITEM` + site `ADD_PAGE UPDATE_PAGE REMOVE_PAGE SET_NAVIGATION UPDATE_SITE`), `SchemaPatchEngine.kt`, `PageSchemaValidator.kt`, `DefaultPageSchema.kt`, `SchemaService.kt`, `version/SchemaCommitService.kt`, `component/ComponentRegistry.kt`, `docs/contracts/app-definition-v2.md`, `docs/adr/` liên quan, `ai/` + `prompt/PromptController.kt` + `integration/llm/*` (AI trả typed operations).
2. Giữ nguyên các khóa hiện có và ý nghĩa của chúng: `page`, `sections`, `pages[]`, `site`, `seo` (đối chiếu thực tế trong code/DefaultPageSchema/validator trước khi chốt).
3. Mở rộng **TÙY CHỌN** (optional, mặc định rỗng/vắng mặt) các khóa: `dataSources[]`, `viewModels[]`, `queries[]`, `mappings[]`, `actions[]`, `workflows[]`, `permissions[]`, `publishConfig`. Mỗi khóa có kiểu typed (data class Kotlin trong `com.systemwebstudio.app.definition`), id ổn định, và **chỉ tham chiếu bằng id** (query tham chiếu dataSource id; viewModel tham chiếu query/mapping id; action tham chiếu viewModel/query/workflow id; binding trong section tham chiếu viewModel/query id). **Không chứa SQL, URL thô, credential hay code.**
4. Tạo `AppDefinitionV2` (+ các định nghĩa con) và `AppDefinitionValidator` theo contract `docs/contracts/app-definition-v2.md`:
   - **delegate** phần page/section/site cho `PageSchemaValidator` — không nhân đôi luật, không sửa hành vi hiện tại của nó trừ khi bắt buộc và có test;
   - validate cấu trúc các khóa V2 mới, id duy nhất, kiểu hợp lệ, độ dài/số lượng giới hạn;
   - **phát hiện tham chiếu chéo sai** (dangling reference, vòng lặp tham chiếu, id trùng) khi có thể — chỉ kiểm tra trong phạm vi định nghĩa (chưa kiểm tra tồn tại thực của DataSource trong DB, đó là việc của giai đoạn sau);
   - trả lỗi có path rõ ràng; `requireValid` ném `ApiException` cùng kiểu với validator hiện tại.
5. **Đường tương thích**: một schema PAGE_SCHEMA hiện tại phải đọc được như `AppDefinitionV2` (adapter/đọc với default rỗng) và vẫn qua `PageSchemaValidator` nguyên trạng. Đề xuất (và cài tối thiểu nếu an toàn) cách `SchemaPatchEngine`/`SchemaOperation` chấp nhận operation V2 **bên cạnh** operation cũ — nếu việc này đòi sửa nhiều hot file, chỉ viết thiết kế trong `DECISIONS.md` (PROPOSED) và dừng ở model + validator.
6. Tạo **sample V2 schema** hợp lệ và một số sample không hợp lệ làm fixture test.
7. Không đổi nơi lưu: `page_schemas` + `project_versions` giữ nguyên. Nếu bạn cho rằng cần cột/bảng mới → ghi request vào BOARD.md (mục Migration requests), **không tự đặt số**, và chốt thiết kế không cần migration nếu có thể (chứa V2 trong cùng JSON).

## 10. What NOT to do
- Không rewrite/đổi tên/xóa Page Schema, `SchemaOperation` cũ, `OperationTypes` cũ; không làm hỏng AI/operation hiện tại.
- Không implement data runtime, query execution, DataGateway, connector, workflow/action runtime, tenant, permission mới.
- Không sửa `access/**` (C1), `data/**` (C3), `logic/**` (C4), frontend (C5), `runtime/Gateway.kt`, `publish/**`.
- Không thêm trường cho phép nhúng code/SQL/URL thô/secret. Không tạo model dữ liệu riêng cho AI. Không migration khi chưa được cấp số.
- Không thay đổi `SchemaCommitService` ngoài thứ tối thiểu cần để gọi validator V2, và chỉ khi có test bảo đảm hành vi cũ bất biến.
