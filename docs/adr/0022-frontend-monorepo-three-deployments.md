# ADR 0022 — Three frontend deployments, one monorepo, shared packages, one backend
Status: accepted (2026-10-06, C0) · supersedes ADR 0001 · **takes effect when the C5 import lands** (`docs/parallel/V2_IMPORT_MANIFEST.md`); until then ADR 0001 still describes the code.

**Context.** The product now has three audiences with different trust levels and release cadences: platform operators (SYSTEM_ADMIN), tenant administrators, and tenant members who build and run apps. ADR 0001 put everything into one Next.js app with one catch-all route and client-side route guards. Branch `agent/c5-web` (D-C5-04) split the frontend into three apps and shared packages, and in doing so replaced ADR 0001's structure **without an ADR** and edited C0-gated root files. This ADR records the decision properly, fixes its boundaries, and keeps what ADR 0001 got right.

**Decision.**
1. **Three frontend deployments**, each built and started on its own: `apps/platform` (SYSTEM_ADMIN, platform scope), `apps/admin` (TENANT_ADMIN and scoped managers), `apps/studio` (tenant members: build, run, publish). Each has its own origin, its own session cookie and CSRF cookie (cookies are per origin), its own `next.config`/CSP, and its own same-origin `/api` + `/oauth2` + `/login/oauth2` rewrite to the API. Dev ports 3001 / 3002 / 3003; bind to `127.0.0.1` in dev scripts.
2. **One monorepo** (npm workspaces, explicit workspace list so the registry-published `packages/app-sdk` and `packages/company-ui` are untouched): `apps/*` plus shared source packages `packages/{types,ui,auth,api-client,permissions,i18n}` (TypeScript source, consumed through `transpilePackages`, no separate publish). Shared code lives in a package; an app imports packages and never another app. The legacy root app (mock static export for GitHub Pages + http mode) and `workers/render` keep building during the migration; old files become re-export shims, moved incrementally.
3. **Shared packages carry contracts, not authority.** `packages/types` is the only mirror of the backend contracts and its header states `MIRROR of docs/contracts/v2/<file>.md @ <commit> — manual`; `packages/permissions` only decides what to *show*. A hidden button is not authorisation: every call is authorised by the backend (ADR 0002 stays in force: the portal choice is navigation intent, never authorization).
4. **One backend: the modular monolith** (`com.systemwebstudio`, Spring Boot, one deployable). **No microservices.** Tenancy, data platform, workflow runtime and AI planner are modules/packages of that one deployable with the layering in `docs/contracts/v2/integration-contract.md` §1; one PostgreSQL, one Redis, one RabbitMQ, one MinIO. Splitting a module into a service needs a new ADR with evidence (load, team boundary, failure isolation).
5. **Who may enter which portal** is decided by the server and mirrored by the UI: Platform = `SYSTEM_ADMIN`; Admin = `TENANT_ADMIN` of the tenant (or scoped manager); Studio = authorised tenant member / resource grant. C5's interim D-C5-05 (all portals follow `me.systemAdmin`) is **TEMPORARY** and is replaced when C1's `MeResponse` exposes tenant roles (it does after the C1 import); the Admin portal is internal-only until then.
6. **Cross-origin rules.** CORS allow-list = exactly the three portal origins (credentials are allowed: never `*`); the OIDC IdP client registers one redirect URI and one post-logout URI per portal and three web origins. See `docs/parallel/WEB_SECURITY_CONFIG.md` §3–4 (including the open single-redirect-URI limitation).

**Consequences.**
- Deployment, CSP and cookies per portal; a compromise or a bad release of one portal does not ship in the others. Three builds per release (CI cost) and three origins to configure (CORS, OIDC, TLS).
- Shared packages need discipline: a change in `packages/types` is a contract change (`docs/contracts/v2/*`), reviewed by C0; `lib/app-definition/contract-mirror.ts` (a second mirror in C5) is deleted.
- The root `package.json`, `package-lock.json`, `tsconfig.json`, `next.config.ts` and `proxy.ts` stay C0-gated: C5's monorepo versions are merged by hand at the import (second commit) and verified with `npm ci && npm run typecheck:all && npm run build:apps && npm run build` in mock and http modes before anything else is built on them.
- Superseded: ADR 0001 ("one frontend, two shells, client-side routing"). Kept from it: one design system, one API client and one session provider **as shared packages**; routing guards only choose a screen and the backend authorises every call; deep links; the static mock export of the legacy app until it is retired.
