## How to read this file
- **ID**: `KL-<area>-NN`, stable within this document. The corpus identifier (blocker `B-...`, finding `FQ-...`, bug `BUG-C6-...`, ledger `M-...`, `LIM-1`) is quoted in the description so the item can be traced.
- **Severity**: P0..P3 only where the corpus rates it (C6 final QA scale: P0 = release stopper, P1 = must close before release, P2 = fix before freeze, P3 = low; see `docs/parallel/c6/FINAL_RC_QA_REPORT.md` on `origin/agent/c6-qa`). `n/r` = the corpus gives no rating.
- **Status**: `OPEN` (a defect or gap that should be fixed or decided), `DEFERRED` (an explicit decision to postpone; the product is consistent without it), `ACCEPTED` (a documented limit with no plan to change). Where a fix is already imported but not independently retested, the item stays `OPEN` and says so. (The vocabulary DONE / PARTIAL / BLOCKED / DEFERRED used elsewhere does not apply to this register.)
- **Source**: `(src: path[:line])`. Dated records say their date; the corpus changes quickly and a row that cites a document older than the final SHA is marked `UNVERIFIED current` when nothing newer confirms it.
- Items closed in the corpus (for example B-C0-W-04/05/06/07, B-C4-11, B-C5-06, H-C1-04, M-052, E2E-ORG01 25d/25e, the C1 hardening fixes of D-C0-60 item 1) are not repeated here.
- "Checked in code" means read or grepped at `integration/v2` `28376ded2307` in this finalization pass.

## Summary of what is NOT done (read this first)
1. **Approvals** are executable since the V33 import (durable `approvals` table, decision route), but: deciding needs `WORKFLOW_MANAGE`, which only WORKSPACE_ADMIN holds, so a decider must be a named approver AND a workspace admin; there is no `APPROVAL_DECIDE`, no approvals inbox, no notifications and no Studio UI for approval decisions or for LIVE actions/workflows. FQ-WF-01/02 await independent retest.
2. **Notifications / NOTIFY action, event dispatch, schedules CRUD, data webhook ingest, AI data catalog adapter** are not wired (skeletons or ports only).
3. **Row-level security, audit tenant column, candidate activation (V31 void), tenant compat removal** are unnumbered / deferred migrations.
4. **Public deployment is not production**: the public API is two generations behind the portals (explicit DEFER), single node, no HA, not zero-downtime, off-host backup missing.
5. **Several feature flags default OFF** (Dynamic Organization persistence, public data runtime, publish configs, data platform, workflow, AI planner, tenant AI, webhooks). **Public data and publish policy have enforcement gaps** (writable-source rule, stored `requiresAuth` / `cacheSeconds`, shared gateway result cache): see KL-DATA-15, KL-PUB-11, KL-DATA-16.
6. **OIDC/SSO can complete on one portal origin only.**
7. **Real AI providers, real IdP, real SCIM tenant, real external data sources were never exercised.**
8. Firefox is BLOCKED_TOOLING; Safari NOT_TESTED; "WebKit" means Playwright WebKit.
9. Open QA items on the last full run (2026-10-10, `bc5c47f292d0`): 2 P1 (FQ-ACT-02, FQ-WF-01), 4 P2, 12 P3; READY_FOR_RELEASE = NO at that time (src: `docs/parallel/c6/FINAL_RC_QA_REPORT.md` section 2). Fixes for FQ-ACT-02, FQ-WF-01/02, FQ-UI-01, FQ-A11Y-02, FQ-PERF-01 are on `integration/v2` but NOT yet independently retested. Four C1 P1 findings and the project-lookup existence oracle are still OPEN in code (KL-IAM-04, KL-IAM-05). The final acceptance run is recorded in [QA_FINAL](QA_FINAL.md) section 8, not here.
